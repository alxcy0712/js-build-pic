# 儿童蜡笔画约定

版本：0.4.0 draft。范围：`naive-source-colors`。两档规范和参数映射以 [drawing-levels.json](drawing-levels.json) 为单一来源；本文件说明共享的内容判断、构图、文字与导出策略。

## 内容判断

绘制前用简短证据回答四件事：主要表达是什么；哪些特征决定主体身份、类别和动作；哪些数量、位置、遮挡及接触影响含义；哪些内容删掉后仍保有同一主体、场景和表达。

- **核心信息**承担身份、动作、必要结构、语义数量或空间关系，用户明确要求也属于核心。两档共享同一核心清单，每项按原图可见证据记录位置、作用和最低充分画法。
- **辅助内容**补充有意义的内部特征、次要结构或场景线索；移除后核心表达成立，可按贡献选择，并用简单线条或色块概括。
- **可省略细节**包括细微纹理、复杂明暗、微小装饰和低贡献重复信息。面积、显著性及配饰身份仅作观察线索，语义作用决定分类。

分析沿用 `core_information` 和 `optional_details` 两个清单：后者承载辅助内容与可省略细节，按贡献排列。`action` 为 `retain / simplify / omit`；选中项排在省略项之前，省略项的 `depiction` 为 `""`、`guide_marks` 为 `[]`。记录选中数量供审阅；计划采用语义取舍，取消固定百分比和配额。

单项与成组移除都核对；全部可选内容移除后，主体身份、动作、必要结构与场景组织仍应成立。密集重复结构可以用少量线条或成组形状概括，保持整体秩序；数量承载语义或用户要求时精确保留。原图遮挡范围内只使用实际可见的证据。

| 原图可见内容 | 两档共享的核心表达 | 可概括或省略的丰富度 |
| --- | --- | --- |
| 人物戴眼镜 | 承担身份辨识的镜框与位置 | 镜片反光、铰链 |
| 房屋有窗户 | 可辨认的窗户结构、主要位置 | 窗框纹样、玻璃反光 |
| 自行车 | 轮子、车架及连接关系 | 密集辐条概括为少量线条 |
| 人物拿手机 | 手机、手与手机接触及动作 | 微小摄像头装饰 |
| 鱼、乐器或机械 | 识别性色带、主要结构或关键关节 | 不承担辨识与功能的表面纹理 |

这些例子用于解释作用判断。具体清单从当次图片建立；证据不足的观察保持未知。人物配饰、建筑开口和遮挡部件都依据当前图中可见内容。

`observation` 记录主要表达、主色与空间关系；`grouping_check` 记录核心与辅助划分的理由；`plan_check` 简述原图和计划是否对应。`source` 是位置及观察证据，`role / importance` 是作用判断，`depiction` 是实际画法。记录保持简短，身份判断困难且影响表达时取得用户确认。

## 两档画法

简笔蜡笔使用更少笔画、概括轮廓、大色块和简单形状，减少局部纹理、小线条、复杂明暗和微小装饰。核心部件与关系完整保留，简化通过改变表达方式完成。

丰富蜡笔多保留有依据且有意义的内部结构、次要特征与少量纹理，全部仍采用简单线条和色块。精细木纹、密集刻画、摄影式光影和工整成人插画属于超出当前画法的表达。

共同的童趣来自朴拙造型、可读的不规整线条、自然涂色与随笔触产生的蜡笔质感。新增装饰以原图证据或用户明确要求为依据；统一噪点、全局抖动及纹理覆盖不能承担造型简化。原图简单时两档接近是合理结果。正常分辨率和合格成图质量适用于两档。

用户每次新的绘画请求独立选择；入口沿本次明确指定或本次询问后的回答传入 `simple / rich`。含糊选择、默认档请求、上次选择和交互超时均保持等待。

## 构图与文字

保留主体主要位置、相对大小、朝向、主要留白、遮挡、接触和互动。儿童式轻微不规则作用于笔画和形状；主体占比、文字牌位置、结构类型与前后景层次以原图为依据。归正后的原图作为生成的第一张参考图，计划稿作为第二张辅助图；Agent 在生成前核对两图。

文字与符号按语义作用判断，文字策略独立于档位。关键招牌、身份符号或用户要求的字符采用 `exact`，逐字保留；无关远景小字可采用 `simplify`，在原位置概括为粗略痕迹。图中出现的所有字符单列在 `image_text`，与规划指令、档位名称和检查项隔离。例如：

```json
{ "source": "原图右上方招牌；字符可读且决定场景", "text": "OPEN", "policy": "exact" }
```

`image_text` 为数组，无需文字时为 `[]`；`simplify` 项的 `text` 可为空，表达观察不到精确字符。`source` 记录原图位置或用户要求的依据。关键文字同时属于核心，写明其作用并保留牌面位置；具体字串集中在文字清单。模板将文字数据单独编排；其余指令只描述如何绘制。生成器的文字能力及指令隔离效果需要实际成图核对，技术检查仅判断文件与比例。

## 逐项审阅

对照原图检查主体身份、动作、核心部件、语义数量与相互关系，再核对构图、选中辅助内容和文字；画法与媒介另行判断。原图中的关键内容遗漏、核心计划过度删减、构图变动、额外内容及文字错误如实记为失败，证据不足保留 `not_run`。技术检查、Agent评审及用户验收分别记录。

评审沿用计划核心项、可选项，并加入文字清单。选中项的实际出现方式及省略项的实际效果逐项记录；原有出现比例仅是固定清单的审计信息，承担精确计数的是具有语义意义的数量。核心保护与两档画法均通过人工对照判断，脚本的完整性检查提供记录约束。

## 导出与维护

导出首先保存生成工具返回的原字节到 `generated-original.bin` 与哈希，解码成功时记录实际格式及归正后的宽高；规范化PNG是展示副本。原件存储在解码与比例校验之前，异常格式或比例的失败结果也保留。校验成功后逐文件暂存并发布，最后提交运行状态；失败使用 `export_failed` 保存原因。重试使用同一原件和一致的完整产物，恢复剩余导出步骤；文件内容冲突保留并报告。原件已经保存时，既有导出入口允许省略生成文件参数。成功导出的重复调用核对已保存文件，继续保留既有评审。

输入及生成结果按实际签名与解码格式检查，动画PNG检查 `acTL`，WebP检查动画块/标志，并检查解码器页数。所有写入限于本skill的真实运行目录，复核目录身份；读取运行文件使用禁止跟随最终符号链接的句柄。不可变产物通过暂存文件和独占发布避免覆盖已有路径；清单与评审通过暂存后原子替换目录项更新。目标符号链接被拒绝；校验后出现的最终文件符号链接也无法引导写入到链接目标。临时文件仅清理当前写入产生的文件。父目录的任意恶意并发替换仍受宿主文件系统接口限制，跨进程行为尚待验证。

0.3%比例相对误差容差作为既有实施政策保留，本地静态样图的比例拒绝与留边恢复已通过技术测试，真实生成工具尺寸量化的适用范围待成图验证。可能来源包括EXIF显示方向、输入缩小的整数像素舍入、生成工具的原生尺寸与尺寸量化；方向归正、原图比例、准备图误差、原件误差和展示副本误差分别处理及记录。比例偏差通过明确失败或经用户接受的留边处理；拉伸、裁掉核心内容和调整阈值都不属于此导出策略。

用户明确接受 `--pad-to-source` 时，只向浅色画布四周加边，保持生成主体像素和完整画面，记录各边像素数；展示副本继续使用相同容差与像素上限。画面内部位置、占比与动作需要人工核对，文件宽高比通过仅代表技术指标。

依赖和目录组织沿用原包，未引入外部素材或新依赖。维护两档提示词在 `drawing-levels.json`，共享内容、构图和文字指令在 `prompt-template.txt`；保持两图输入顺序与一次生成政策一致。

## 接口迁移

0.4.0用户档位为简笔蜡笔、丰富蜡笔，API与命令行值为 `simple / rich`。旧 `low / medium / high` 均返回明确错误，要求按本次意图重新选择；`medium`没有等价的新档位。旧档位基于细节配额，新档位基于画法与语义简化，保留责任统一。所有缺省调用继续进入等待选择状态。

运行清单schema更新为0.2.0，`detail_budget`改为描述性的 `detail_selection`，移除比例配额和目标组数；增加两图输入顺序、生成原件与导出状态。分析增加可选 `image_text` 数组，未提供时按空数组处理。评审改用画法、简化和文字来源检查，并覆盖文字计划。调用方需接受导出失败、原件已保存及导出重入状态。

当前代码只处理0.4.0运行，旧版本清单返回版本迁移错误。历史运行、输入、失败证据和报告保留原样；处理旧运行使用对应Git版本。历史规格与反馈保存在CHANGELOG、验证记录和Git，当前任务从最新入口及本次输入建立计划。

2026-10-05初次改造按用户分工实施代码、文档与静态差异审查。2026-10-06用户确认0.4.0用于主分支与下一次release；发布准备将 `tests/workflow.test.mjs`迁移至两档、语义取舍、旧运行拒绝和导出恢复接口，并补充文字隔离与留边恢复覆盖。本skill独立安装与33项技术回归通过，绘画规则、提示词和执行脚本沿用已合并实现。当前新成图的主体保留、构图、文字与画风待视觉回归，状态保持draft。报告R1与R2各自是历史批次，提供排查线索，验证范围分别记录。
