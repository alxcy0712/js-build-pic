# 绘制参考稿数据

`guide_marks` 将当前任务的最低充分画法转成通用形状。Agent 查看原图后确定位置、颜色、遮挡和辨识笔画，脚本仅负责按计划绘制。原图提供内容与构图依据，参考稿提供简化辅助；两图按此顺序交给生成器。

坐标按归正后的原图归一化为 0–1：左上为 `[0, 0]`，右下为 `[1, 1]`。核心项和选中可选组各自提供至少一个形状；省略组的 `guide_marks` 为 `[]`。

`role / importance / action` 表达内容作用与保留、概括、省略的取舍。每个形状独立提供 `draw_order`：0–9999之间的整数，整个核心与选中项计划内唯一，数值越小越先画。根据原图可见的前后关系，从背景、后方物体、前方物体到各自表面线索安排顺序。同一语义项的形状可以跨越多个顺序；脚本统一排序，语义清单和形状数组的位置都只承担组织记录的作用。

例如，后方辅助色区为10，核心主体为20，主体上的开口为30，原图实际遮挡主体下部的前景辅助物体为40。可见辨识笔画绘在所属表面上方，原图的实际遮挡保持对应。先对照原图核对两份参考稿中的辨识、连接、开口、接触与覆盖关系。0.4.0分析迁入当前版本时补齐 `draw_order`；旧运行继续使用原Git版本。

| type | 位置字段 | 用途 |
| --- | --- | --- |
| rect | box: `[x, y, width, height]` | 大色区与矩形结构 |
| ellipse | box: `[x, y, width, height]` | 圆形与椭圆形色区 |
| polygon | points: `[[x, y], …]`，至少3点 | 轮廓与不规则色区 |
| line | points: `[[x, y], …]`，至少2点 | 辨识笔画与线性关系 |

面积形状使用 `fill`；轮廓和线使用 `stroke` 与 `width`。颜色为六位十六进制色值或 `none`；线宽相对画布短边，范围 `(0, 1]`。全部坐标落在画布内。每项最多200个形状，单个线或多边形最多128点，全图最多1000个形状。文字字符和策略单列在 `image_text`，当前项的 `depiction` 说明文字的作用、位置及牌面画法，其区域用上述形状表达。渲染器使用锁定的 sharp，将经过数字、形状和颜色校验的 SVG 直接栅格化；字体、外部文件和外部 URL 依赖为零。

例如，一个当前任务中的色区可以写为：

```json
{ "type": "polygon", "draw_order": 20, "points": [[0.2, 0.3], [0.55, 0.32], [0.5, 0.6]], "fill": "#ad6842", "stroke": "#563e2a", "width": 0.008 }
```

`core-reference.png` 使用平涂几何，只包含按 `draw_order` 绘制的核心形状。先将其直接对照原图，检查主体身份、动作、内外结构、连接及语义数量；两档共享核心清单。`plan-reference.png` 包含核心和选中项，以当前档位生成粗钝轮廓、往返叠涂和笔触内露纸。笔触尺度跟随局部形状，关键线的端点和连接保持原坐标；前景露纸使用不透明纸底。具体机制、确认范围与seed见[参考稿设计](guide-design.md)。

再核对完整计划稿的选中项、遮挡、比例、朝向、位置、主色与留白；粗略线索应可读。原图简单时两档接近合理。修订分析后使用新的渲染目录准备。实际生成按 `input.png`、`plan-reference.png` 的顺序输入两图；核心参考稿用于 Agent 的最低表达核对。
