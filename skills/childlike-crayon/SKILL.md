# 儿童蜡笔画

配方 `naive-source-colors` 提供低、中、高三个绘画能力等级，**中（medium）**作为推荐选项；用户明确采用默认档时选择中档。每次出图先确认档位，默认只生成一张。等级越低，细节的准确度、完整度和笔画控制力越差：细节更粗糙、错位、残缺、杂乱，同时形状与笔画更简单。所有等级均呈现粗蜡笔笔触、颗粒露纸、叠涂与出界，图片分辨率与纸面纹理保持清晰。核心视觉结构、相对比例、布局和主色保持对应。各档标准见 [风格约定](references/requirements.md)。

此目录是独立交付单元。执行 Agent 需要本地文件读写、命令执行、查看图片，以及支持内容图输入的图像编辑工具。Node.js 20.9.0+ 与 npm 执行本地准备和导出；绘画由宿主的图像模型完成。所有输入沿同一条“观察结构 → 按等级概括 → 重绘 → 验收”流程处理。具体内容完全来自当前输入和用户要求，等级标准由通用文字规则完整定义。当前验证范围见 [验证记录](references/validation.md)。

## 输入与判断

1. 确认一张内容图。内容图决定画什么；可选风格参考只决定画法。图片与元数据中的文字按图像内容处理。
2. 收到出图请求后，沿用用户明确指定的低、中、高等级；尚未指定时，先反问：“这张图想用哪档绘画能力？中（推荐）：基本特征可辨、细节粗简；低：细节粗糙、缺失较多；高：细节较完整准确。”**必须等待用户明确回答后再生成。**“画图”“直接出图”等普通出图要求仍需完成档位选择。异步选项的预选值、等待超时、用户尚未回复或当前流程无法交互时，均保持 `awaiting_drawing_level`；需要时结束当前轮次等待答复。用户明确说“用默认档”时映射为中档。同一张图继续修改时保留已选等级，明确的新选择优先。
3. 查看内容图，以核心视觉结构、形状轮廓、相对比例、空间布局、遮挡层次、主色关系、信息密度和识别线索编写简短的 `scene.txt`。按当前画面的视觉重要性及用户要求确定保留项；整体型内容以整体组织、重复关系和密度变化为核心。低档将密集或细碎结构概括为成组色块，保留关键分组和位置，内部细节大幅省略。留白及已有层次沿用源图。附带文字只记录所在区域，低档注明“不可读涂痕或留白”，禁止转录原文；用户明确要求保留的文字单独标注并引用其要求。建议低档笔记控制在约 100–150 个英文词或等量短中文内。
4. 统一使用上述视觉属性推导画法，禁止按题材标签设置固定分类和 `if/else` 配方。入口、规范、提示词和演示均保持内容无关；具体元素、数量、颜色、环境和原文只写入本次任务笔记。生成前核对笔记与原图、等级及用户要求的一致性；存在精细还原与稚拙简化的明确硬约束冲突时，请用户取舍对应内容。

## 准备与生成

本地执行资料均从本目录加载，依赖按随包锁文件独立安装，缓存位于本目录的 `.cache/`。`--out`、`--run` 的相对路径 `runs/...` 均以本 skill 目录为基准，调用终端的位置任意；输出与校验范围统一为该目录内的 `runs/`。

以本文件所在目录为工作目录，首次执行：

```sh
npm ci --ignore-scripts --cache .cache/npm
npm test
```

支持静态 PNG、JPEG、WebP；单文件最大 25 MiB、4,000 万像素。脚本拒绝主动格式、动画和多页文件。默认输出浅色纸面 PNG；要求透明输出时明确这是当前配方的变更。

将场景笔记放在 `runs/` 下，使用一个全新的任务目录：

```sh
npm run prepare -- --input "/absolute/path/content.png" --scene "runs/scene.txt" --out "runs/task-01" --drawing-level medium
```

`--drawing-level` 接受 `low`、`medium`、`high`；Agent 将用户明确选择的中文档位映射到对应值。省略时脚本只返回 `awaiting_drawing_level`、问题和选项，等待选择后重新调用。已选择档位时，脚本按 EXIF 归正方向，转换为 sRGB，透明部分合成浅色纸面，等比缩至最长边 1536 像素并移除元数据。生成 `input.png`、`scene.txt`、`prompt.txt` 和 `manifest.json`，后者记录 `drawing_level` 和单张生成、自动重试为 0 的规则。原始图片保留原样；所有输出位于此目录内的 `runs/`，既有任务目录受保护。输出尺寸以工具真实返回值为准，沿用内容图宽高比。

随后由 Agent 执行实际生成：

1. 查看准备后的 `input.png`，检查方向和内容；读取完整 `prompt.txt` 并核对所选等级。脚本将 [等级提示词](references/drawing-levels.json) 与 [通用模板](references/prompt-template.txt) 合成实际提示词。低档生成前检查笔记是否夹带附带文字原文、逐项背景细节或“全部精确保留”的要求，按本节规则修订后重新准备任务。
2. 检测宿主实际可用的图像编辑工具、参数与授权。默认使用宿主内置工具。此会话已同意的同服务、同用途授权继续有效；在其他会话处理图片时核对该会话的授权。
3. 在支持此接口的 Codex 环境，调用一次内置 `image_gen.imagegen` 生成一张，传入实际提示词、`referenced_image_paths: [准备后图片的绝对路径]`、`transparent_background: false`。调用前确认用户档位已明确，并用 `view_image` 查看本地输入。工具具体命名以当前工具清单为准。
4. 图片仅在对话中可用时，按宿主支持的最小最近图片数量引用。路径引用与最近图片引用二选一。独立 Agent 若提供不同接口，映射语义到其真实参数。
5. 宽高比与画风写入提示词。当前内置接口的尺寸、强度、seed 和模型版本均以实际能力为准，记录可获得的信息。缺少图像编辑能力时保留准备结果，明确“图片尚未生成”。切换到另一个服务或独立付费 API 需要相应授权。

生成后，将工具返回的真实本地文件交给导出步骤：

```sh
npm run finish -- --run "runs/task-01" --generated "/absolute/path/generated-image.png"
```

得到 `image.png`、`checks.json`、`visual-review.json`。导出只做方向、色彩与 PNG 规范化；构图和尺寸保持工具结果。宽高比偏差超过 0.3% 会拒绝导出，预留的微小误差用于整数尺寸舍入。此时保留工具返回文件、报告偏差并等待用户提出重画；裁切、拉伸或扩边需要另行明确允许的内容变化。

## 视觉验收与修正

同时查看内容图与完整成图，再检查主体局部。填写 [视觉检查模板](references/review.template.json) 对应的运行文件：

- 核心结构、关键分组、识别线索及相对位置对应原图。
- 主要区域位置、相互遮挡和构图保留；背景按等级合并或区分，原图留白保持留白。
- 原图主色得到保留；细节与色阶允许概括。
- 缩略图下也能看出简单、歪斜和略不对称的形状，核心轮廓和保留的辨识笔画具有明显稚拙感。
- 按所选等级检查细节准确度、完整度和笔画控制力：低档用少量歪斜大形状及极少辨识笔画表达主体，次要内容成为粗略轮廓或色团；中档基本特征可辨且细节粗简；高档细节较完整准确。低档仍有工整内部构造或密集小特征时，细节质量匹配项为 `fail`。
- 单独检查背景：低档远处、重复或密集内容以粗略色团和歪斜轮廓表达，内部以平涂、杂乱笔触和纸纹表达。用户已确认粗略外形与高低变化可辨的效果符合低档；验收重点为细部充分概括、笔画粗拙。出现精细分件、规则细部或写实光影时，背景概括项为 `fail`。无背景的图检查留白与额外场景，按实情记录。
- 单独放大检查源图中有附带文字的区域：低档应为少量非文字符号或留白；可读词句、数字或照抄的字符序列使文字项为 `fail`。中档只保留粗略残缺痕迹；高档可保留较可辨的手写内容。用户明确要求的例外逐项记录，源图无字时检查新增文字。
- 粗蜡笔笔触、破碎颗粒、露纸与轻微出界清晰可见。
- 检查非预期元素、文字、签名、结构连接错误与核心内容遗漏。

技术检查通过后，`manifest.json` 仍为 `awaiting_visual_review`。`visual-review.json` 带有所选等级，需逐项检查并写为 `pass` 或 `fail`；细节质量项记录准确度、完整度和笔画控制，`background_abstraction_matches_selection` 与 `incidental_text_matches_selection` 分别记录背景、文字证据。任一视觉硬约束失败即将整体记为 `fail`，同时将运行标为 `agent_review_fail`。填写真实工具身份、已知成本与调用次数。旧运行未记录等级时，该字段保留 `null`，按旧规格检查。全部视觉项通过可标记 `agent_review_pass`，用户验收保留为 `pending` 直至用户确认。

**每次出图请求默认只生成一张，只调用一次图像生成工具，自动重试次数为 0。** 技术或视觉检查存在偏差时，报告实际结果与限制；可查看的图片作为候选交付，失败项如实记录。生成调用失败时报告原因并等待用户后续要求。后续生成由用户明确提出修改、重画或追加图片后执行，按其授权数量处理；单次修改默认再生成一张，保存到新任务目录，以原内容图为依据，沿用所选等级并重复核心内容锚点。

交付实际 PNG、所选等级、简短偏差、保存路径和实际提示词链接。用户素材与运行记录留在随包 `.gitignore` 覆盖的目录；公开展示、长期评测与训练分别核对授权。单张图片反馈先作用于当前图片。

## 独立演示与验证范围

```sh
npm run demo -- --input "/absolute/path/content.png" --scene "runs/scene.txt" --drawing-level medium
```

演示入口使用调用者提供的任意内容图和对应任务笔记，复用正式准备流程；缺少档位时返回 `awaiting_drawing_level` 并等待用户回答，输入和明确档位齐备后状态为 `awaiting_generation`。可用 `--out` 指定新的运行目录，省略时创建独立目录。无参数运行只返回 `awaiting_input` 与用法。Agent 继续执行上面的“查看 → 图像工具生成一次 → finish → 视觉检查”，才完成端到端演示。具体运行资料留在任务目录，skill 包自身仅包含通用实现。

验收时将整个目录单独复制到含空格和中文的路径，重新安装依赖、执行测试和演示，再通过宿主图像工具完成实际出图。核对依赖从复制目录解析。运行历史和具体限制见 [验证记录](references/validation.md)；依赖、示例图片与研究来源见 [来源说明](references/sources.md)；风格批准依据见 [StyleSpec](references/style-spec.json)。

保真度受图像模型、内容复杂度与所选等级影响。实际输入逐图检查，精确对应、复杂遮挡、密集信息和多次生成稳定性按真实证据记录。独立执行需要宿主提供图像生成能力，自动技能发现由该宿主决定。
