# 逐图缩小形态设计

模型负责每次设计；`design.mjs` 负责把已给定的轮廓变成同一种马赛克粒子。所有上传图片都作为独立输入完成以下步骤，即使题材相同，也从各自的姿态、比例、局部特征与颜色重新判断。

1. 观察当前源图与 `subject-N.png`，记下最有辨识度的可见结构及空间关系。
2. 自行选择适合小尺度的概括方式，写出具体设计及其与该图的联系。可以突出特征局部、概括整体姿态或重组几个关键结构；轮廓需要在实际输出尺寸下可辨认。
3. 自行绘制归一化多边形，分部件指定从当前 `subject-N.png` 的哪里取色。源图的细节、姿态与主色应体现在设计中。坐标与内容判断留在当前任务。
4. 按上传顺序把逐图设计写入 `designs.json`，预览各自的缩小帧并检查实际视觉对应关系。多图逐项审阅；相同题材的两张图片也要分别完成观察与设计理由。

执行边界：通用代码仅接受模型提供的几何数据，省略设计时直接报错。具体物体的造型、题材分支、通用图标库和固定缺省轮廓均排除于生产执行逻辑；前一张图的造型只能作为已完成的当前图设计记录，后续图片重新分析。演示与测试中的形状只属于其生成的测试素材。

## JSON 契约

顶层为数组，长度等于输入图片数量，按上传顺序逐项提供：

| 字段 | 含义 |
| --- | --- |
| `image_index` | 从 1 开始，严格对应输入顺序 |
| `label` | 模型为这张图拟定的简短造型说明 |
| `reason` | 该图具体视觉证据，以及如何概括成当前设计；最多 1000 字符 |
| `parts` | 1～16 个多边形部件，后面的部件覆盖前面的部件 |
| `parts[].polygon` | 3～256 个 `[x,y]` 顶点，坐标均在 0～1；模型逐图绘制 |
| `parts[].source_region` | `[left,top,width,height]`，在当前透明方形 `subject-N.png` 中的归一化取色矩形 |

`source_region` 必须包含当前图片的可见采样单元。模型可以先以内部 PNG 模式生成并查看主体，再确定实际取色位置。该区域提供原图 RGB；某部件需要的颜色由该图自己的区域提供。

轮廓按 64×64 网格取样、保持比例、居中适配到画布约 26% 的范围。这里的固定数值控制缩小展示尺度；轮廓、部件和取色位置均来自当次设计。固定编号粒子从当前图的缩小形态扩散，再落到该图的马赛克采样位置。

## 审阅与复现

`animation.json` 记录逐图 `designs`、`compact_tracks`、完整目标与固定粒子分配。`manifest.json` 记录实际输入、设计、档位和输出哈希；每个部件的取色记录可追溯到该图的源采样单元。更换设计应只改变缩小形态与运动，成图停留帧保持该图的完整马赛克。

结构检查覆盖数量、顺序、几何、取色边界、逐图绑定、渲染一致性及循环；内容是否准确、有辨识度，由执行模型逐图检查并记录。每次任务设计保持私有；通用 skill 保留流程、格式与渲染能力。
