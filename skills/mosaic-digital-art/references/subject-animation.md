# 主体与动画执行

`0.7.2` 先确认分辨率，逐图提取主体并独立设计缩小形态，最终只交付 GIF。每图 5.4 秒，完整马赛克停留 1 秒。选择规则与优先级以 [入口](../SKILL.md) 为准。

## 主体提取

蒙版为不透明灰度 PNG，与源图应用 EXIF 后的尺寸一致：白色保留、黑色清除。Agent 或分割工具负责确定主体；随包多边形工具按明确坐标生成蒙版。复杂发丝、镂空和互相遮挡需更细致的选区，视觉检查记录实际近似。

`subject.mjs` 在采样前把蒙版乘入源透明度，清除全透明像素中的背景 RGB，裁去外围空白，再保持主体比例放入带 4% 边距的透明方形画布。已抠好的透明素材可直接输入。`subject-N.png` 是可检查的提取结果；既有 `subject-focus` 的 25% 背景减量仅用于明确指定的历史复现。

当前图中被物件遮住的部位保留其可见边界。裁切边缘、透视与主体姿态沿用源图。人物以人物本身为主体；确需保留的道具按用户要求处理。

## 多图输入

`images.json` 是按展示顺序排列的数组。路径可为绝对路径，或相对于该清单的路径。每张不透明源图都提供自己的蒙版；已经透明的主体图省略 `subject_mask`。

```json
[
  {"input":"photo-a.png","subject_mask":"mask-a.png"},
  {"input":"subject-b.png"}
]
```

```sh
npm run render -- --images "/absolute/path/images.json" --designs "/absolute/path/designs.json" --representation irregular-shapes --resolution medium --out runs/sequence
npm run verify -- --run runs/sequence
```

同一序列统一使用形状、binary 或 mixed。每张图按 [逐图设计](compact-design.md) 提供自己的形态、理由及取色区域，依次展示该图的缩小形态、扩散和马赛克。主体数量和密度不同仍使用固定粒子池；较小目标的空余粒子收缩至零，下一次重排可再次参与。按空间次序匹配位置，沿连续曲线重排，过渡期间插值采样颜色。最终停留帧精确还原该图的结构表示。

## 分辨率档位

向用户提供低、中、高三个选项，中档为推荐默认。缺少选择时等待用户回答；明确选择“默认”时用中档。已指定档位或具体尺寸的当前请求直接沿用其选择。

| 档位 | 输出尺寸（GIF 与 PNG） | 采样网格 | 视觉取向 |
| --- | --- | --- | --- |
| 低 `low` | 512×512 | 64 列 × 48 行 | 粗颗粒、较小文件 |
| 中 `medium` | 896×896 | 128 列 × 96 行 | 当前效果，兼顾颗粒感与细节，推荐默认 |
| 高 `high` | 1536×1536 | 256 列 × 192 行 | 更密的色块或字符，保留更多轮廓与内部细节 |

高档的采样格数量为中档的四倍。三档均从提取后的主体重新采样并渲染，保留所选的单一构成元素。原图和蒙版的清晰度仍影响最终细节。GIF 的 256 色限制在各档保持一致。

通过 `--resolution low|medium|high` 选档。CLI 缺省值为 `medium`；Agent 调用前仍须按入口确认用户选择。显式 `--width` / `--columns` 使用 `custom` 记录，和 `--resolution` 分开使用。内部 PNG 预览添加 `--format png`。

## 参数与输出

| 参数 | 默认与范围 |
| --- | --- |
| `--input` / `--images` | 单图路径 / 多图 JSON，二选一 |
| `--subject-mask` | 单图蒙版；多图使用清单中的逐图蒙版 |
| `--designs` | GIF 必填，按图片顺序独立设计的 JSON 数组，格式见 [逐图设计](compact-design.md) |
| `--representation` | 必填，Agent 选择 `irregular-shapes` 或 `characters` |
| `--format` | 默认 `gif`；`png` 仅用于内部预览及验证，一次处理一图 |
| `--charset` | 字符默认 `binary`，明确乱码使用 `mixed` |
| `--resolution` | `low` / `medium` / `high`，中档为 CLI 缺省值；按用户确认选择 |
| `--width` | 自定义 96～1536，方形画布，主体保持比例 |
| `--columns` | 自定义 8～256，宽度至少为列数的 6 倍；随档位增加真实采样密度 |
| `--seed` | 42；32 位无符号整数 |
| `--out` | 本 skill 的 `runs/` 中的新目录；相对路径以 skill 目录为基准 |

时序为 25 帧/秒，每张图独立占 5.4 秒、135 帧；总时长为图片数乘 5.4 秒。以下时间相对每张图自己的开场：

| 阶段 | 时间位置 | 时长 |
| --- | --- | --- |
| 缩小形态展示 | 0～0.4 秒 | 0.4 秒 |
| 扩散 | 0.4～1 秒 | 0.6 秒 |
| 汇聚成马赛克 | 0.8～3 秒 | 2.2 秒，与扩散重叠 0.2 秒 |
| 完整马赛克停留 | 3～4 秒 | 1 秒、25 帧 |
| 收拢到下一张图的缩小形态 | 4～5.2 秒 | 1.2 秒 |
| 循环衔接停留 | 5.2～5.4 秒 | 0.2 秒 |

扩散后半段便开始汇聚，两段重叠 0.2 秒；各粒子错峰启动；收拢紧接停留帧启动并平滑落回缩小形态。末图收拢回首图的缩小形态。输入为静态 PNG、JPEG 或 WebP，单文件最多 25 MiB、4,000 万像素；图片清单与设计 JSON 各最多 128 KiB。

动画总像素预算为 10 亿像素，5.4 秒时序下像素预算允许高档至多 3 张、中档至多 9 张。超预算时在创建输出目录前返回错误，Agent 说明图片数量和选定档位的限制，等待用户选择减少图片或降低档位。高档的生成耗时、内存和文件体积会增加，实际资源失败按同样方式处理。GIF 的调色板与二值透明度属于格式限制；本地 PNG/结构表示保留完整采样颜色与透明度。

内部输出包括 `subject-N.png`、`image-N.png`、`extraction.json`、`scenes.json`、`manifest.json`、`checks.json` 与 `animation.json`。最终交付仅为 `animation.gif`，列在 `manifest.deliverables`。manifest 的 `resolution` 记录档位、宽高和列数，`designs` 逐图记录模型设计；将 `style_spec_ref` 指向含用户选择依据的实际规格，Agent 视觉检查另存记录。

`npm run verify` 核对 GIF 交付清单、输出哈希、所有内部成图的结构、逐图设计对应的缩小形态、GIF 帧数与时序、首尾像素、固定粒子分配、每段关键帧颜色误差与透明区域。内部静态预览也使用这一检查入口。每张图的设计语义、连续运动观感及蒙版质量仍需 Agent 逐阶段检查。

本流程仅使用锁定的 Node.js 依赖 `sharp`，GIF 编码随包提供。任务版的本机绝对路径与 FFmpeg 临时脚本保留在历史运行记录中。
