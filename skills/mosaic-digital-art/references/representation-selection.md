## 选择依据

用户已指定构成元素时直接沿用。普通“数字化”“艺术感”“爆散成像”请求由模型观察内容图后选定一种，记录 `representation` 和一句话 `selection_reason`，直接执行。

| 路径 | 适合的表现 | 判断重点 |
| --- | --- | --- |
| `irregular-shapes` | 色块、自然轮廓、抽象重构、有机碎片运动 | 不规则面片在目标尺寸下能否保留主体，色块关系能否传达原图氛围 |
| `characters` | 编码感、可辨识字形、字母数字重构、文字起始的成像动画 | 字形在目标尺寸下是否清楚，疏密与色彩能否保持主体辨识 |

题材用于辅助判断；表达重点、内容辨识和最终尺寸共同决定选择。明确的 0/1、乱码或本项目约定的黑客帝国字符画请求使用字符路径。技能标识本身仅用于路由。

选定后整幅作品只采用该元素类型：形状路径的主体与细节都由闭合的不规则面片构成；字符路径的主体与细节都由所选字符集构成。单一底色、透明底、留白及画布外的界面文字按对应输出规格处理。原照片作为采样输入。

## 两条执行路径

当前由模型逐图提取主体并独立设计缩小形态，`npm run render` 执行设计并生成 GIF，统一执行 `npm run verify`。具体单图、多图及内部预览见 [主体与动画执行](subject-animation.md)。以下底层静态命令用于历史场景复现与技术验证。字符静态入口为 `render:characters` / `verify:characters`，默认 0/1；明确乱码使用 mixed。

形状路径使用同包脚本，输入限制、RGBA 采样、蒙版及背景保留逻辑与字符路径一致；输出由各采样格内的闭合不规则六边形构成。固定种子决定顶点位置，间隙露出统一底色。默认宽度 1536、列数 128；参数包括 `--width`、`--columns`、`--seed`、`--background`、`--subject-mask`、`--background-density`。

```sh
npm run render:shapes -- --input "<本地内容图的绝对路径>" --out runs/<新任务目录>
npm run verify:shapes -- --run runs/<新任务目录>
```

`shapes.json` 保存采样色、透明度、可见性和多边形顶点。`strict_shapes` 检查元素类型及顶点边界，重放几何与色彩并比对 PNG；额外字符、照片层或未声明的后处理会使像素检查失败。该检查证明导出与声明的几何一致，主体辨识和审美另做视觉检查。

## HTML 与动画

当前最终只交付主体爆散循环 GIF。多张图使用同一粒子池，按上传顺序依次经历各自设计的缩小形态、扩散及马赛克成像。GIF 使用随包 sharp 编码，尺寸、帧率、时长和循环均须检查。

- 形状路径：用不规则面片构成模型为当前图片设计的缩小轮廓；爆散、移动、最终成像和循环回收均使用同一批面片。
- 字符路径：用同一字符集构成模型为当前图片设计的缩小轮廓；字符的聚集位置、局部取色随该图设计决定。
- 每个元素固定对应一个最终采样区域，用连续位置轨迹及缓入缓出完成运动，最终落位保持原图采样色和主体结构。按实际密度调整数量与尺寸，检查开场、爆散中段、汇聚中段、最终画面和循环衔接。

动画执行已内置在 `scripts/animate.mjs`，覆盖两种元素、两种字符集、单图爆散和多图重排。各图最终成像逐张结构校验；关键动画帧与 GIF 编码另行检查。视觉检查涵盖蒙版、运动及每次切换。先前“形状开场、字符成像”的混合样例属于旧探索，后续沿用单一路径。
