# RENDER_IMAGE

在用户要求实际图片转换时读取本文件。主要交付物为图片，附简短的风格、版本和重要偏差说明。

1. 读取索引，确认候选 skill 的实现与验证状态；缺少能力时说明缺口，明确用户选择可复用创建或单次临时处理。
2. 区分内容图和风格参考图；仅有参考图时请求内容图。询问会明显影响画面的缺口，复用用户已给定的画法、保留范围与约束。
3. 按所选 skill 自带的规格、模板与工作流记录本次参数，说明低影响默认值。普通出图在规格充分且授权有效时直接执行。
4. 执行时才加载所选配方、渲染器及必要资产；核验真实工具、尺寸、输入角色、支持参数、授权和预算。只运行必要且已审查的代码。
5. 生成并检查实际图片。失败时记录原因，在授权预算和明确重试上限内修正；仍有问题时报告剩余缺口。
6. 允许本地记录时，在对应 `skills/<id>/runs/<task-id>/` 保存输入副本、输出、规格与该 skill 的运行记录。反馈默认只作用于当前图片，通用改动转入优化流程。

## 渲染与验收

- 确定候选风格后，从索引读取其约定文件；专属构造规则、参数和验收项由对应风格与配方定义。
- 正确处理来源方向、宽高比与透明度；保留确认的内容，内容替换需明确许可。
- 根据视觉目标和实际能力选择代码、图像模型或混合路径。近似方案须说明可达到的效果并取得认可。
- 将内部参数映射为真实支持的接口参数；服务身份、外传、预算与保留政策按证据记录。
- 对配方要求的中间表示和最终图片完成结构与视觉检查；后处理后重新核验硬约束。
- 记录代码或提供商版本、环境、相关资产标识及实际可用的随机种子，复现范围限定为已验证环境。

执行前检查文件类型、文件大小、像素数量及输出路径；SVG 等主动格式先进行安全处理。缺少运行或生图能力时交付已完成的规格或代码，并明确图片尚未生成或验证。
