# CREATE_SKILL

在新增可复用风格能力时读取本文件。读取当前状态、风格索引与相关研究，确认应新建家族、增加配方或添加参数预设。

1. 复用已有说明和已确认约定。新家族、名称、素材、依赖或服务做相称的联网调研，记录 URL、访问日期、证据类型、许可与未核验项。
2. 每轮只询问最影响结果的 2～4 个缺口；单一关键缺口只问一次。逐步明确使用场景、主体、正反参考、媒介与技法、保留范围、改造程度、输出、工具、预算、隐私和验收标准。
3. 用 [StyleSpec 模板](../shared/templates/style-spec.template.json) 记录用户原话、字段状态和默认值。核心审美、保留范围及硬约束消歧后，提交下面的《风格确认单》并取得确认。探索样张只在获得相应用途授权后制作。
4. 检查可用工具与参数，选择获准的代码、图像模型或混合路径，定义检查方法与重试上限。先完成一张真实内容图的端到端样例，再根据反馈修正。
5. 将有效方法整理成 `skills/<id>/SKILL.md` 和必要资源。实现前读取 [渲染约束](render-image.md)，验收时读取 [评测流程](evaluate-skill.md)。
6. 在约定范围内检查代表输入、失败案例及保留验证样本。取得版本与范围确认后更新索引、CHANGELOG、项目状态与决策记录；证据尚未齐备时保留 `draft`。

## 风格确认单

用一小段可审阅文字说明：风格家族和配方、可见的目标效果、适用主体、必须保留内容、允许改动、明确排除效果、输出规格、工具与数据流向、预算、验收标准、低影响默认值、仍待回答的问题。用户已明确授权代选的事项写入依据。

## skill 交付内容

- 入口：YAML frontmatter 的 `name` 与目录名一致，采用小写字母、数字及连字符；`description` 包含适用与排除场景。版本等信息置于 `metadata` 或项目索引。
- 能力：输入、澄清条件、风格定义、默认值、参数范围、硬约束、执行流程、渲染器选择、失败处理与已知限制。
- 资源：从入口直接写明在何种条件下加载哪个配方、脚本、人物规则或检查文件。只创建当前需要的资源。
- 证据：至少一个实际可运行样例、输入输出说明、检查结果、依赖和素材授权、版本说明。具体配方注明适用主体、视觉目标、避免偏差与验收点。

真实图片尚未生成时，可交付规格草案和文件，并明确标记“尚未生成图片”及剩余验收项。稳定能力需要在声明的范围内积累证据。
