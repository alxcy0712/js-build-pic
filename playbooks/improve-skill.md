# IMPROVE_SKILL

在用户明确要求改进通用 skill 时读取本文件。

本轮规格、样图和验证日志保存在对应 `skills/<id>/runs/<task-id>/`；跨 skill 修改分别记录各自的执行资料。Git 版本提供回退依据；当次源码副本仅用于执行审计，按 Git 文件清单和明确纳入交付的新文件构建。

目录整理、引用修正等维护按用户已授权范围执行，保留既有视觉规则。删改前检查全部调用方，尤其是入口、提示词、规范、模板和命令示例；修改后执行 `npm run check` 与相应回归。历史摘要记录当时结果，恢复源码时应用当前目录边界。

1. 识别反馈范围：`current_image` 调整本次参数；`user_preset` 经确认保存个人预设；`global_skill` 进入本流程。作用范围存在关键歧义时先澄清。
2. 读取 Git 管理的当前版本、相关规格和通用验证结论，核对当次输入及用户反馈。明确纳入交付的新文件一并审阅；运行证据来自本次新建产物。历史 runs、旧缓存与本机私有资料按用户明确授权的范围读取。缺失证据写明缺口。
3. 定位问题：需求理解、路由、定义、参数、实现、模型能力、素材质量或验收方式。提出可检验假设，优先只改变一个主要因素。
4. 调整通用视觉规则时，提交包含影响范围、前后预期、验收标准与回退影响的《风格确认单》，取得确认后实施候选版本。用户本次已明确的同范围授权继续有效。
5. 按 [评测流程](evaluate-skill.md) 对本轮相同输入和可比设置做前后对照，检查其他已支持配方；按 Git 交付清单构建项目外独立副本，从空运行记录全新安装并执行测试与真实演示，清理后使用新输入再走完整流程。模型随机性、服务版本差异、真实耗时与可获得成本如实记录。
6. 硬约束和回归通过后，向用户提交可审阅的候选结果，取得稳定版替换确认；更新索引、CHANGELOG 和项目状态。

开发样本与保留验证样本分开，测试按固定能力维度组织。开始前记录实验阶段与合理调用上限；冻结候选后使用未参与调优的输入检查，失败项继续按新阶段解决。普通出图沿用所选 skill 的单张与重试规则；将私人反馈图纳入长期测试集前核对授权。

每次版本记录旧版、新版、原因、改动文件、证据位置、已知限制与恢复方式。保留 Git 提交及必要的本地授权样例；恢复时保护当前未提交工作，仅恢复此次变更范围。

单次出图参数留在当前任务记录。模型训练、微调或上传参考集作为独立的数据与费用操作审批。
