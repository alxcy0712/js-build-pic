# EVALUATE_SKILL

在评估路由、效果、稳定性、授权或版本差异时读取本文件。记录实际运行环境、输入授权与验证范围。

## 检查维度

| 维度 | 所需证据 |
| --- | --- |
| 硬约束 | 保留范围、排除内容、`strict_01` 中间表示和最终图片检查 |
| 内容保留 | 人脸、主体、姿态、布局等与确认规格的对照 |
| 风格符合 | 媒介、笔触、色彩、纹理与目标的对照，注明评审者和依据 |
| 缺陷 | 畸形、乱码、过曝、糊化、非预期文字、水印或签名 |
| 泛化与回归 | 代表输入、已支持配方、开发样本与保留验证样本的覆盖 |
| 执行 | 路由结果、实际加载文件、耗时、失败率、真实可获得成本 |
| 权限与版本 | 数据用途、外部传输授权、依赖许可、版本与回退证据 |

事实观察、自动检查、人工审美判断与待验证推断分开记录。填写 `pass`、`fail` 或 `not_run`，缺少证据的项目保留 `not_run`；量化分数需要可复核测量依据。

## 初始验收场景

以下为待执行的验收用例，当前初始化阶段尚未进行 Agent 路由实测或图像效果评测。

| 输入或场景 | 预期行为 |
| --- | --- |
| “转成国风” | 澄清关键画法及保留范围 |
| “淡墨写意，保留人脸和姿态，不换衣服，不加字” | 复用已给规格，匹配能力并处理实际缺口 |
| 本项目的“黑客帝国风格” | 沿用全 0/1 构图定义，生成后做结构与视觉检查 |
| “0 和 1 的编程题” | 按编程请求处理 |
| 仅有风格参考图 | 请求补充内容图 |
| “这张再淡一些” | 只调整当前任务参数 |
| 现有索引只有 `planned` 家族 | 说明能力待建设，确认创建或临时处理路径 |
| 新增现有家族未支持的配方 | 交付时说明候选与验证状态 |
| 工具不可用、预算不足、验收失败 | 报告完成项与具体缺口 |

活跃 skill 可逐步准备约 10～20 条路由正反例及覆盖约定范围的授权图片。数量随实际覆盖需要确定。当前表格是测试计划，实际运行后单独保存结果与证据。

通过标准：确认的硬约束全部通过，相关回归完成，剩余限制可见，版本范围经用户确认。自动评分用于辅助判断，目标风格由用户验收。
