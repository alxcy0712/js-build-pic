# EVALUATE_SKILL

在评估路由、效果、稳定性、授权或版本差异时读取本文件。记录实际运行环境、输入授权与验证范围。

## 检查维度

| 维度 | 所需证据 |
| --- | --- |
| 硬约束 | 保留范围、排除内容、配方结构要求，以及必要的中间表示和最终图片检查 |
| 内容保留 | 主体特征、布局及指定保留内容与确认规格的对照 |
| 风格符合 | 媒介、笔触、色彩、纹理与目标的对照，注明评审者和依据 |
| 缺陷 | 畸形、乱码、过曝、糊化、非预期文字、水印或签名 |
| 泛化与回归 | 代表输入、已支持配方、开发样本与保留验证样本的覆盖 |
| 执行 | 路由结果、实际加载文件、耗时、失败率、真实可获得成本 |
| 独立运行 | `npm run check` 检查入口、提示词、文档链接、代码引用、依赖与退役目录；`npm run test:standalone` 将 skill 单独复制到含空格和中文的项目外路径，使用副本内的缓存安装锁定依赖，执行测试和演示；模型出图及视觉验收按实际范围另行记录 |
| 权限与版本 | 数据用途、外部传输授权、依赖许可、版本与回退证据 |

事实观察、自动检查、人工审美判断与待验证推断分开记录。填写 `pass`、`fail` 或 `not_run`，缺少证据的项目保留 `not_run`；量化分数需要可复核测量依据。

## 通用验收要求

按以下类别组织评测，具体用例与已完成的实际结果维护在对应风格或测试目录。各类验证状态按证据分别记录。

| 输入或场景 | 预期行为 |
| --- | --- |
| 风格目标存在关键歧义 | 澄清关键画法及保留范围 |
| 用户已给出充分规格 | 复用已给规格，匹配能力并处理实际缺口 |
| 风格包含专属结构约束 | 沿用已确认定义，生成后做结构与视觉检查 |
| 请求与风格词汇近似、用途不同 | 根据实际任务意图路由 |
| 仅有风格参考图 | 请求补充内容图 |
| 用户反馈明确针对单张图片 | 只调整当前任务参数 |
| 现有索引只有 `planned` 家族 | 说明能力待建设，确认创建或临时处理路径 |
| 新增现有家族未支持的配方 | 交付时说明候选与验证状态 |
| 工具不可用、预算不足、验收失败 | 报告完成项与具体缺口 |

活跃 skill 可逐步准备约 10～20 条路由正反例及覆盖约定范围的授权图片。数量随实际覆盖需要确定。当前表格规定覆盖类别，实际运行后单独保存结果与证据。

通过标准：确认的硬约束全部通过，相关回归完成，剩余限制可见，版本范围经用户确认。自动评分用于辅助判断，目标风格由用户验收。
